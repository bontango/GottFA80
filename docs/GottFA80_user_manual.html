Important remark

By using GottFA80 it is possible to damage your pinball machine. As this is a private project with NO commercial interest the author accepts no liability for any damage that may arise by using GottFA80!

1. Introduction

GottFA80 replaces the MPU of your Gottlieb System80, System80A or System80B game. The soundboard and the driver boards of your machine stay as they are. For a board with integrated soundboard see GottFA80_PLuS and GottFA80S.

GottFA80 is a 100% hobby project. This makes the solution cheap; depending on where you buy your components it is possible to build your Gottlieb replacement MPU for less than 50 €.

What do you need?

  • Basic soldering skills
  • Possibility to read/write micro SD cards (not needed if the game roms are in the FPGA flash, chapter 10)
  • A PC with an USB port and an USB Blaster in order to be able to program the FPGA
  • Gottlieb rom images (not included due to copyright limitation)

1.1. New in software x.05

Software x.05 is the first version built from the common GottFA80 source tree, which since November 2026 holds GottFA80 together with GottFA80_PLuS and GottFA80S.

  • Game roms in the FPGA flash. If no SD card answers, the boards with Cyclone IV or Cyclone 10 read the game roms from the flash memory the FPGA itself boots from (chapter 10).
  • Text boot display on System80B games (chapter 6.3).
  • Clearer boot display. Player 2 shows the game number with three digits, player 4 the setting of the option switches (chapter 6.2).
  • SD card diagnosis by blink codes of the 'SD card' LED (chapter 6.1).
  • Cyclone II (105): now runs the same program as the other boards. Late System80B and game roms in the flash are not possible on it (chapter 8.4).

Test status: x.05 has been tested on the Cyclone 10 board (405, with game roms in the flash). The other boards have not been tested with x.05 yet; chapter 8.4 lists the last released file for each board.

1.2. New in 306: FA-Control on board v4.x

Only for the Cyclone IV board v4.x. Version 306 contains everything of 305 and adds FA-Control: with the small ESP32 piggyback on the JTAG connector of the FPGA board you watch the running game in your web browser (lamps, solenoids, switches, displays), simulate switches, and take over the machine to test lamps, solenoids, sounds and displays. Nothing else changes, without the piggyback 306 runs exactly like 305. Details in chapter 11.

2. Soldering

On my website I provide the bill of material, and on the PCB each component is named. The anode of the LEDs is marked with an 'A'.

Only with a Cyclone II FPGA board from AliExpress: you need to solder an additional 2-pin connection on the FPGA board and a 2-pin socket on the PCB. With this connection GottFA80 supplies 5 Volt to the FPGA board, no additional power supply needed! My own FPGA boards (Cyclone IV, Cyclone 10) do not need this.

Solder the 2-pin connector here (missing on the picture).

3. Quickstart

  1. Download the latest versions of the SD card image and the FPGA program from lisy.dev - the FPGA program for your FPGA board, see chapter 8.4
  2. Write the image to a SD card (chapter 7)
  3. Add Gottlieb roms (chapter 9)
  4. Program the FPGA (chapter 8)
  5. Configure switch 'game select' according to your pinball (Appendix A)
  6. Set S2-Dip2 'init nvram' to ON for the first start
  7. Replace your original System80 MPU with GottFA80
  8. Switch the game ON - then switch it off, set S2-Dip2 back to OFF and switch it on again
  9. Enjoy

For all my 'FA' boards you will find a user manual on the 'product page'. However all these boards have in common that you need to:

  1. select a SD card which works with my 'FA' boards
  2. put the image to the SD card
  3. buy or build an USB Blaster
  4. program the FPGA

Information about my different DIY FPGA boards you can find here.

4. Installation

GottFA80 boards have the same connectors and the same mounting holes as the original Gottlieb System80 MPUs, so replacing the board can be done in seconds.

With 306 on the Cyclone IV board v4.x you can additionally plug the FA-Control piggyback onto the JTAG connector P5 of the FPGA board, also with the board installed in the machine (chapter 11).

5. Dip Switch Settings

The four DIP banks on the left (S1...S32) are the same as on the original MPU. The two banks on the right are for game selection and the GottFA80 options.

A DIP switch is 'ON' when it is pushed to the 'ON' side of the bank. The numbers shown on the boot display count the switches that are ON (chapter 6.2).

FA-Control (306, chapter 11) needs no DIP switch: you request the takeover in the FA-Control web page.

5.1. Game select

Here you select which game GottFA80 runs. The six switches form the game number in binary: Dip1 = 1, Dip2 = 2, Dip3 = 4, Dip4 = 8, Dip5 = 16, Dip6 = 32, so the game number is 0 to 63.

Which game has which number depends on the roms on the SD card. See chapter 9 for the structure of the SD card and Appendix A for the arrangement on my SD card image.

5.2. S2 options

5.2.1. S2-Dip1: Freeplay

With Dip1 'ON' GottFA80 reads the free play version of the selected game from the SD card - slot 'game number + 64' (chapter 9.2). My SD card images ending in '_FP' contain these free play versions.

In addition 'press and hold' of the credit button simulates a coin in the left coin chute while the game is running.

The normal and the free play version of a game share the same nvram.

5.2.2. S2-Dip2: Init nvram

With Dip2 'ON' GottFA80 initializes the nvram of the selected game to zero during boot. This is useful if you want to reset ALL ram content (recommended for the first start of a game). Set it back to OFF afterwards, otherwise all settings and high scores are cleared at every power on.

5.2.3. S2-Dip3: Slam contact open

With Dip3 'ON' the slam contact is simulated as 'open', independent of the real contact. The late System80B games need this. Dip3 has priority over Dip4.

5.2.4. S2-Dip4: Slam contact closed

Most System80 games need the slam contact to be closed and will not boot in case the slam contact is open. With Dip4 'ON' the slam is simulated as 'closed', independent of the real contact.

With Dip3 and Dip4 both OFF the real slam contact of the machine is used.

5.3. Gottlieb DIP banks

The four banks S1...S32 are the same as on the original MPU. Consult the manual of your pinball to see how they affect the game behavior.

6. Boot sequence

6.1. Phase 1: loading the game roms

Immediately after switching on, GottFA80 reads the game roms of the selected game from the SD card. If no SD card answers, the boards with Cyclone IV or Cyclone 10 read them from the FPGA flash instead (chapter 10). With a card in the slot the card always wins.

If reading fails, the red 'SD card' LED shows what went wrong, player 4 shows 0000000 and the game does not start:

SD card LED Meaning
blinks 3 times (1 s on, 1 s off), then stays on the card does not answer at all (no card, card not inserted properly)
blinks 4 times, then stays on the card does not answer the SDHC check - very old or unsuitable card
blinks 6 times, then stays on the card does not finish its initialisation
blinks fast, pause, again and again game roms from the flash: the slot of the selected game is empty (chapter 10)

6.2. Phase 2: info display

Until the game program takes over, the displays show:

Display Content
Player 1 version of the FPGA program running, for example 305 - the first digit tells you the board (chapter 8.4)
Player 2 game number with three digits, for example 014 (without the free play offset)
Player 3 050963 - lisy.dev identifier for FPGA based MPUs
Player 4 the S2 options, for example 08: Dip1 = 1, Dip2 = 2, Dip3 = 4, Dip4 = 8. 0000000 means the game roms could not be read (chapter 6.1).

6.3. Boot display of System80B games

System80B games (game number 40 to 61) have alphanumeric displays. On these GottFA80 shows a text boot display:

Row Content
1 GOTTFA80 V305 - name and version
2 GAME 040 OPT08 - game number and options as in chapter 6.2
2, roms from the flash GAME 040 FLASH ROM
2, no SD card GAME 040 NO SD CARD
2, other SD card error SD E3 ... - blink code and the answer of the card, for support
2, slot in the flash empty FLASH ERR GAME 040

6.4. Phase 3: program execution

The game program is started. If it runs (regular interrupts are seen), the yellow LED goes ON and the game takes over the displays.

7. Put the GottFA80 image to the SD card

On lisy.dev you find the latest version of the GottFA80 SD card image as a (zipped) image file, with my arrangement of the games (Appendix A). The images ending in '_FP' contain the free play versions as well (chapter 9.2), the images ending in '_Blank' are empty and are meant for your own roms (chapter 9). GottFA80, GottFA80_PLuS and GottFA80S use the same image.

After unpacking, write the image to a SD card. I recommend Win32DiskImager for that, see put the image to the SD card:

8. Programming the FPGA

To program the FPGA you need the Quartus Programmer and an USB Blaster.

8.1. Programmer software

It can be downloaded from the Intel website for free, you just need to create a user account.

  • Cyclone IV and Cyclone 10 boards: in the download section of Quartus Prime Lite Edition (version 22.1 or later) go to 'Additional Software' and download Quartus Prime Programmer and Tools. The old Quartus II 13.0sp1 does not know the Cyclone 10 LP.
  • Cyclone II board: Intel has discontinued support for Cyclone II. Use the Quartus II 13.0sp1 Programmer ('Additional Software' of version 13.0sp1) if it is still available; newer programmers have worked as well.

8.2. Install the driver for your USB Blaster

When connecting your USB Blaster the first time it will not be recognized correctly by Windows.

You need to install the driver for your USB Blaster. The driver comes together with the installation of the programmer and is located in its 'drivers' subdirectory.

  • Right click on the entry in the device manager and choose 'update driver'
  • Choose 'search for driver on this PC'
  • Select the 'drivers' folder of your programmer installation
  • Confirm installation
  • Now the Altera USB Blaster should be visible under 'USB-Controller'

8.3. Program your FPGA

  1. Connect the USB Blaster to the PC

  2. Start the programmer, make sure in the Hardware setup 'USB-Blaster' is visible and set the Mode to 'JTAG' (Cyclone IV and Cyclone 10). For the Cyclone II board set the Mode to 'Active Serial Programming'.

  3. Select 'Add File' and choose the right file for your FPGA board (chapter 8.4): the 'jic' file for Cyclone IV and Cyclone 10, the 'pof' file for Cyclone II. Select the 'Program/Configure' and 'Verify' options.

  4. Power the board, then connect the USB Blaster to the JTAG connector of the FPGA board (Cyclone II: the 'AS programming' connector). Push start and wait for progress 100%. That's it!

The screenshots show an older version of the programmer and another FA board; the current one looks almost the same.

The same design runs on several FPGA boards, and the FPGA program is not interchangeable between them - the pin assignment differs. The first digit of the version shown on player 1 at boot tells you which program is running.

9. Structure of SD card

Due to limitations of the SD card read routine in the FPGA (it reads fixed sector numbers instead of looking for filenames) it is necessary to use my SD card image (about 120 MByte). You can write the image to a SD card of your choice, any size equal to or bigger than 128 MByte will work. The card has to be a SDHC card (that is what you get today with 4 GByte and more).

Note: 'Sandisk' SD cards can not be used with GottFA80!

9.1. Rom file structure

For each game GottFA80 reads a 16 KByte block from the SD card. Every block starts at sector 660 + slot number x 32 and has this layout:

Offset Size Content
0x0000 2 KByte game rom, e.g. '668-4.cpu'
0x0800 2 KByte second game rom - only the late System80B games (4 KByte game rom), otherwise fill
0x1000 4 KByte sound roms - used only by GottFA80_PLuS and GottFA80S, GottFA80 ignores this part
0x2000 8 KByte system rom, e.g. 'u2_80.bin' + 'u3_80.bin'

The gaps have to be filled, so that every block has exactly 16 KByte. There is no checksum.

9.2. Game selection and free play

The first rom file you copy onto the empty ('_Blank') SD card image will be selected with game select '0' (all OFF), the second with '1' (all OFF except Dip1) and so on.

As the FPGA just reads fixed sector numbers the filename is not relevant, you can choose whatever filename you want. It just needs to be placed at the right position on the SD card. You 'select' the position of the rom file on the SD card with the order of your file copy. Make sure each file has exactly 16 KByte.

With S2-Dip1 'freeplay' ON GottFA80 reads slot 'game number + 64'. So the free play versions follow behind the 64 normal games, in the same order: slot 64 is the free play version of game 0, slot 78 that of game 14 and so on.

9.3. Examples

The files '1K' ... '7K' do not contain any data and just exist to fill the gaps. They can be downloaded from my software repository on lisy.dev. All commands are for a windows command prompt. As GottFA80 ignores the sound part, it is simply filled with 4K.

Black Hole (2 KByte game rom, two 4 KByte system roms):

copy /b 668-4.cpu + 2K + 4K + u2_80.bin + u3_80.bin blckhole

Raven (System80B: 2 KByte game rom 'prom2', 8 KByte system rom 'prom1'):

copy /b raven2.cpu + 6K + raven1.cpu raven

Bad Girls (late System80B: 4 KByte game rom):

copy /b badgirls2.cpu + 4K + badgirls1.cpu badgirls

Rock (System80B: only one 8 KByte rom, no separate game rom; also valid for Bounty Hunter, Chicago Cubs Triple Play and Rock Encore):

copy /b 2K + 6K + rock.cpu rock

10. Game roms in the FPGA flash

New with software x.05, on the boards with Cyclone IV (205, 305) and Cyclone 10 (405), not on Cyclone II. The FPGA boots from a flash chip (EPCS16, 2 MByte) on the FPGA board, and the space behind the FPGA program can hold the game roms of all 64 games and their free play versions. A board with roms in the flash runs without SD card.

  • With a card in the slot the card always wins. So you can still try other roms from a card without touching the flash.
  • If the card is missing or does not answer, the board reads the flash. The SD card LED does not light then.
  • There is no checksum. GottFA80 only checks that the slot of the selected game is not empty; an empty slot shows the flash blink code (chapter 6.1).

The roms are copyrighted, so they cannot be part of the download from lisy.dev. You put them there yourself, from your own SD card image:

  1. Build the rom file. In the GottFA80 source tree (github.com/bontango/GottFA80) run

     scripts\make_flash_hex.ps1 -Image <image file> -Out variants\<variant>\output_files\gottfa80_roms.hex -Verify

    The script takes every slot that contains a game. Identical 2 KByte parts (the system roms, the fill) are stored only once, so all 128 slots of my image fit.

  2. Build the FPGA program of your board in the folder variants\<variant> and run quartus_cpf -c gottfa80_roms.cof there. This puts the FPGA program and the roms into one file, output_files\gottfa80_roms.jic.

  3. Program gottfa80_roms.jic with the Quartus Programmer instead of the normal file, with 'Verify' ticked (chapter 8.3).

The variant names of the source tree are smd_hw11_cyclone_iv (205), smd_hw11_cyclone_iv_v4 (305) and smd_hw11_cyclone_10 (405).

Keep that file to yourself. It contains the game roms and must not be passed on.

11. FA-Control over the JTAG piggyback (306)

New with 306, only on the Cyclone IV board v4.x. FA-Control is a small ESP32 board with a web page: you open it on your phone or PC and see what the game does, or take over the machine for testing. Its own manual: FA-Control user manual.

What you need

  • 306 in the FPGA (chapter 8.4)
  • the JTAG piggyback with FA-Control firmware 1.34 or later, connected by ribbon cable to the JTAG connector P5 of the FPGA board. It is powered from the board, no extra supply needed.
  • WLAN for your phone or PC

Never connect the USB cable of the piggyback and the ribbon cable at the same time. Firmware updates go over WLAN.

What it does

  • Monitor mode - the game keeps running. The web page shows lamps, solenoids, sounds, switches and both displays, also the two text lines of System80B games. You can close switches for the game (e.g. the credit switch), up to four at the same time. They are released automatically when the web page is closed.
  • Control mode - FA-Control takes over. The game stops, and you switch lamps, pulse solenoids, play sounds and write the displays (System80B: two text lines with 20 characters). If the connection is lost for 2 seconds (piggyback unplugged, WLAN gone), GottFA80 gives the machine back by itself. After DISCONNECT the game starts again as after switching on.

The piggyback uses the same connector as the USB Blaster. To program the FPGA with the USB Blaster (chapter 8.3), unplug the piggyback first. FA-Control can also write the FPGA program itself (menu FPGA in the FA-Control web page).
